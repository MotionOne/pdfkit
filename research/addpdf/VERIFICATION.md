## 3. 단위 테스트 61건이 검증하는 것

### 3.1 객체 변환 (`pdf_bridge.spec.js`, 15건)

pdf-lib이 읽은 객체를 pdfkit이 쓸 값으로 바꾸는 층이다. 여기서 틀리면 파일이 조용히
깨지고, 뷰어는 열리지만 내용이 다르다.

| 검증 | 왜 중요한가 |
|---|---|
| 문자열이 문자열로 남는다 | 이걸 놓치면 `(Watermark)`가 `/Watermark`라는 **이름으로 새어나간다**. 번들 환경에서 `Buffer.isBuffer`가 node Buffer를 인식하지 못해 실제로 발생했던 버그다 |
| hex 문자열이 hex로 남는다 | UTF-16 텍스트가 깨지지 않는다 |
| 이름이 pdf-lib 직렬화와 정확히 같다 | `PANTONE#20185#20C` 같은 `#` 이스케이프가 유지된다. 별색 이름이 어긋나면 분판이 갈린다 |
| 숫자·불린·null | `PDFNull`은 클래스가 아니라 싱글턴이다. `instanceof`로 쓰면 즉시 예외 |
| 배열·딕셔너리·중첩 | 리소스 그래프 전체가 이 두 가지로 이루어진다 |
| 같은 참조는 한 번만 복사 | 폰트·이미지가 중복 기록되지 않는다 |
| 간접 객체가 문자열·이름·배열일 때 | 딕셔너리가 아닌 값을 펼치면 `/Name (Watermark)`가 `/token /(Watermark)`로 변형된다. **코퍼스 회귀가 잡은 실제 버그** |
| 원본 스트림이 바이트 단위로 기록된다 | 재인코딩이 없어야 JPEG 화질과 폰트가 그대로 유지된다 |

### 3.2 원본 읽기 (`pdf_source.spec.js`, 11건)

| 검증 | 왜 중요한가 |
|---|---|
| 경로·Buffer·Uint8Array 입력 | `doc.image()`와 같은 입력 집합을 보장한다 |
| 암호화 PDF를 명확한 메시지로 거부 | 거부하지 않으면 암호화된 바이트가 그대로 실려 **열리지 않는 PDF**가 조용히 나온다 |
| PDF가 아닌 입력도 거부 | 실패가 늦게 드러나지 않게 한다 |
| 페이지 크기를 pt로 보고 | 배치 수학의 입력이다 |
| 요청한 박스를 보고, 없으면 MediaBox로 | 조판은 TrimBox 기준으로 앉힌다 |
| 회전 페이지는 가로세로를 바꿔 보고 | `/Rotate 90`이면 실제 표시 크기가 뒤바뀐다 |
| 범위를 넘는 페이지 인덱스 거부 | 잘못된 주문 데이터가 조용히 1페이지를 앉히지 않게 한다 |

### 3.3 배치 (`pdfs.spec.js`, 35건)

**크기와 위치 (11건)** — 출력 content 스트림의 `cm` 연산자를 직접 대조한다. 예를 들어
`{ width: 306 }`은 `q\n0.5 0 0 -0.5 40 456 cm\n/Fx1 Do\nQ`가 되어야 한다. 기본 1:1,
width만, height만, 둘 다, scale, fit, cover, align, valign, 커서 전진, 체이닝.

| 검증 | 왜 중요한가 |
|---|---|
| 크기 미지정 시 1:1 | 조판의 기본값. 이미지와 다른 규칙이라 명시적으로 고정해 둔다 |
| `fit`/`cover`의 한계축 선택 | `doc.image()`와 같은 규칙이어야 호출부가 혼동하지 않는다 |
| `doc.y` 전진 | 흐름 배치에서 다음 요소가 겹치지 않는다 |

**Form XObject와 캐시 (5건)**

| 검증 | 왜 중요한가 |
|---|---|
| 페이지 리소스에 form으로 등록 | 배치의 기본 구조 |
| `box` 옵션이 BBox를 바꾼다 | TrimBox 기준 앉힘이 실제로 반영되는지 |
| 같은 페이지 두 번 배치 → form 1개 | 없으면 N장 앉힐 때 출력이 N배로 커진다 |
| 다른 box → form 2개 | 같은 페이지를 다른 기준으로 앉힐 수 있어야 한다 |
| 같은 경로 재오픈 → 같은 핸들 | 재파싱 비용을 없앤다 |

**회전 (4건)** — `/Rotate` 0·90·180·270 각각에서 form Matrix가 맞아야 한다. 예를 들어
90도면 `/Matrix [0 -1 1 0 0 600]`. 이게 틀리면 **원고가 90도 돌아간 채 인쇄된다.**

**투명도 (1건)** — `/Group`을 복사하지 않으면 블렌딩이 깨진다. 코퍼스 60개 중 24개가
`/Group`을 갖고 있다.

**레이어 (10건)**

| 검증 | 왜 중요한가 |
|---|---|
| 카탈로그에 OCG 등록 | 레이어는 카탈로그 레벨 정보다. 페이지만 복사하면 뷰어가 `/OC` 참조를 해석할 근거가 없다 |
| 중복 등록 안 함 | 같은 파일을 여러 번 앉혀도 레이어 목록이 늘어나지 않는다 |
| OFF 상태 유지 | **재단선 레이어가 꺼진 채로 납품되는 파일**이 켜져서 나오면 안 된다 |
| BaseState `/OFF` 유지 | 전체 기본 숨김 설정을 쓰는 파일이 있다 |
| 패널 순서를 원본 `/Order`대로 | `/OCGs` 순서로 재구성하면 순서가 뒤바뀐다. 실제 파일에서 발생 |
| 원본에 `/Order`가 없으면 만들지 않음 | 없던 구조를 임의로 만들지 않는다 |
| `/RBGroups` 이관 | 상호 배타 레이어(옵션 선택형)가 동작해야 한다 |
| 레이어 이름 유지 | 조판 담당자가 패널에서 알아볼 수 있어야 한다 |
| `/OC ... BDC` … `EMC` 유지 | 어느 내용이 어느 레이어에 속하는지의 근거 |
| form 리소스의 `/Properties` 연결 | 위 마킹이 가리키는 대상 |

**실패 경로 (2건)**

| 검증 | 왜 중요한가 |
|---|---|
| 디코딩 실패 후에도 문서를 끝낼 수 있다 | 할당한 객체를 정리하지 않으면 `_waiting`이 0으로 돌아오지 않아 **문서 생성이 영구히 멈춘다**. xref도 `%%EOF`도 없는 파일이 남는다 |
| 범위 초과 페이지는 쓰기 전에 거부 | 부분적으로 망가진 출력을 만들지 않는다 |

## 4. 하네스 검증 항목과 결과

### 4.1 구조 검증 — 모든 하네스 공통

생성한 PDF를 **독립적인 파서**(`prototype/miniparse.js`)로 되읽어 확인한다. 우리가 쓴
코드로 우리 출력을 검증하지 않기 위한 장치다.

| 항목 | 의미 |
|---|---|
| xref 오프셋이 모두 `N 0 obj`를 가리킨다 | 오프셋이 틀리면 뷰어가 객체를 못 찾는다 |
| `/Root`에서 그래프가 전수 해석된다 | 끊긴 참조(dangling ref)가 없다 |
| 모든 스트림의 `/Length`가 실제 바이트와 일치 | 어긋나면 그 지점부터 파일 전체가 깨진다 |
| 배치된 XObject가 `/Subtype /Form`이다 | 구조가 의도대로 만들어졌다 |
| content가 `/Fx1 Do`를 호출한다 | 실제로 그려진다 |
| 문자열이 Name으로 새지 않았다 | 3.1의 그 버그에 대한 회귀 방어 |

### 4.2 코퍼스 회귀 — `corpus.js`

```
=== doc.addPdf over 60 real PDFs ===
SUCCESS 59   FAILED 1
  1x  Cannot place an encrypted PDF. Remove the encryption first.
ms per file: median 33, max 2244
streams copied: 23692
```

유일한 실패는 암호화 파일이고 의도된 동작이다. 23,692개 스트림이 재인코딩 없이 복사됐다.

### 4.3 프리프레스 수용 검증 — `acceptance.js`

Altona PDF/X-3(11.7MB)를 프리프레스 기능을 켠 문서에 두 번 배치한 결과.

```
page 1 media  : 1250.55103 x 901.88995 pt
page 1 trim   : 1190.55103 x 841.88995 pt
openPdf       : 107ms
total         : 128ms, peak RSS 94MB
output        : 11.8MB
```

| 항목 | 결과 | 의미 |
|---|---|---|
| xref·그래프·`/Length` | PASS (248객체, 101스트림) | 구조 정합 |
| form XObject | PASS `BBox=[30,30,1220.55,871.89]` | TrimBox 기준으로 앉았다 |
| 두 배치가 form 1개 공유 | PASS (`/Fx1 Do` 2회) | 캐시 동작 |
| 네이티브 pdfkit 내용 공존 | PASS | 우리가 그린 것과 섞인다 |
| 우리 TrimBox·BleedBox | PASS | 원본이 우리 설정을 덮지 않는다 |
| 우리 OutputIntent | PASS | PDF/X 출력 조건이 유지된다 |
| 색공간 대조 | PASS `ICCBased 7→7, Separation 6→6, DeviceN 3→3, DeviceCMYK 28→28, Indexed 4→4` | 별색과 ICC가 그대로 넘어왔다 |
| 스트림 바이트 동일성 | PASS (93개 추적) | 재인코딩 0 |

### 4.4 레이어 보존 — `check-layers.js`

코퍼스의 레이어 파일 **13개 전부 통과**. 4레이어 생산 파일의 결과:

```

        ON     : ["디자인뒷면","칼선뒷면","디자인","칼선"]   OFF: []
```

| 항목 | 의미 |

| 그리기가 선택하는 레이어 | 내용과 레이어의 연결이 유지된다 |

### 4.5 교차 검증 — `crosscheck.js`

우리 출력을 pdf-lib으로 되읽는다. **경고 0건.** 미묘한 기록 오류를 독립 구현으로 확인하는
장치이고, 실제로 이것이 문자열 누출 버그를 처음 드러냈다.

## 5. 아직 사람이 해야 하는 확인

구조와 바이트는 자동으로 검증했지만 **화면에 어떻게 보이는지는 확인하지 못했다.** 이
머신에 Ghostscript 델리게이트가 없어 ImageMagick으로 PDF를 래스터화할 수 없다.

Acrobat이나 생산 RIP에서 확인해 주셔야 하는 것:

| 파일 | 볼 것 |
|---|---|
| `sample-1to1.pdf` + 원본 | 별색 패치가 같은지(출력 미리보기 → 분판), CMYK 수치가 같은지, 재단 영역이 맞는지 |
| `sample-layers.pdf` | 레이어 패널에서 `디자인`/`칼선` 토글이 동작하는지, 특히 재단선만 껐다 켜지는지 |
| 회전 원본 | `/Rotate 90`인 파일을 앉혔을 때 방향이 맞는지 |
| 투명도 원본 | `/Group`이 있는 파일의 블렌딩이 원본과 같은지 |

추가로 남은 것: **Electron 4 렌더러에서 번들이 실제로 로드되는지.** `copy.bat` 후 앱에서
확인이 필요하다.

## 6. 이 검증들이 실제로 잡은 버그

구현 중에 자동 검증이 잡아낸 것들이다. 어떤 층이 무엇을 잡는지 보여주기 때문에 기록해 둔다.

| 버그 | 증상 | 잡은 것 |
|---|---|---|
| 문자열이 Name으로 누출 | 원본 `/CharSet (/period/space)`가 `/CharSet /period/space`로 기록 | 방식 비교 단계의 교차 검증 |
| 간접 객체 값이 딕셔너리가 아닐 때 펼침 | `/Name (Watermark)`가 `/token /(Watermark)`로 변형 | 코퍼스 회귀 (단위 테스트는 놓쳤다) |
| `/Order`를 `/OCGs` 순서로 재구성 | 레이어 패널 순서가 뒤바뀜 | 레이어 보존 검증 |
| 원본에 없는 `/Order`를 생성 | 없던 구조가 생김 | 레이어 보존 검증 |

단위 테스트만으로는 두 번째 버그를 잡지 못했다. **실제 파일 코퍼스를 함께 돌리는 이유가
이것이다.**
